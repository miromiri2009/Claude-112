# 8. Технический стек

## 8.1 Движок: решение

**Рекомендация:** прототип и MVP — **Godot 4**, продакшн — **Unreal Engine 5**. Повествовательные данные с первого дня живут вне движка, поэтому переезд обходится без переписывания контента.

| Критерий | Godot 4 | Unreal Engine 5 |
|---|---|---|
| Скорость прототипа (2 недели) | ✅ Очень быстро, GDScript, лёгкий проект | ⚠️ Тяжёлый старт, C++ / Blueprints |
| Detroit-уровень лиц и эмоций | ❌ Нет аналога MetaHuman | ✅ MetaHuman + Live Link Face (лицевой захват с iPhone) |
| Свет, ночной город, дым | ⚠️ Хватит для MVP | ✅ Lumen, Niagara (дым, огонь, снег), Nanite для города |
| Консоли | ⚠️ Через сторонние порты | ✅ Нативно (PS5 / Xbox) |
| Лицензия | MIT, без роялти | 5 % роялти после $1 млн выручки (проверить актуальные условия на момент старта) |
| Команда и найм | Небольшой пул | Большой пул |

**Итог:** в Godot 4 проверяем петлю «звонок → дорога → прибытие → ядро → развилка → отчёт → смерть/наследство». Как только петля «работает» на игроках, переносим её в UE5 вместе с теми же данными (Ink + YAML).

## 8.2 Архитектура контента (одинаковая для обоих движков)

```
content/
  heroes/            # 9 YAML: способности, слабости, шкалы, риск смерти
  missions/
    3_3_camellia/
      mission.yaml   # паспорт, таймеры, NPC, фазы, точки смерти
      kirill.ink     # диалоги и варианты версии героя
      litvin.ink
      ...
  flags.yaml         # реестр флагов (см. docs/04_story/flags.md)
  endings.yaml       # условия 27+1 концовок
  locations/         # точки на карте Воронежа, маршруты, звуковые ландшафты
```

- **Диалоги и ветвление — Ink** (inkle, MIT). Плагины: `godot-ink` для Godot, `Inkpot` для UE5. Сценаристы пишут в Inky, программисты не трогают тексты.
- **Механика миссий — YAML-граф фаз:** таймеры, QTE, улики, условия на флагах, точки смерти.
- **Флаги** — единый глобальный стор (ключ → значение) с журналом изменений: какая миссия и какой герой изменили флаг. Журнал нужен «Летописи» и отладке.
- **Сохранение** — снимок флагов, состояния героев, наследства и «Летописи» после каждой фазы (без ручного сохранения: смерть не откатывается).

**Инструмент QA ветвлений (обязателен):** скрипт, который строит граф 25 миссий × 9 версий и проверяет:
- у каждой версии 6 фаз и 5–8 вариантов на фазу;
- у каждой развилки ≥ 6 вариантов;
- каждая из 27 концовок достижима хотя бы по одному пути;
- нет флагов, которые где-то читаются, но нигде не пишутся;
- у каждой точки смерти есть флешбэк, последняя запись и наследник.

## 8.3 Ключевые системы (порядок реализации)

1. **Пульт / рация:** звонок как аудиопоток, колесо вопросов, таймер, выбор служб, «Фильтр» (серые карточки).
2. **Способности** («Оценка» и 8 вариантов): общий модуль slow-mo (`Engine.time_scale` / `Global Time Dilation`) + слой подсветки + «стамина фокуса».
3. **Мини-игры первой помощи:** давление, жгут, СЛР (ритм 100–120/мин с допуском ±10), восстановительное положение, FAST-тест инсульта, ожоговая повязка. Протоколы валидирует медицинский консультант (см. раздел 10).
4. **QTE:** окна с цветом риска (обычное / чёрная рамка ✝), адаптация под доступность (удержание вместо мэша, увеличенные окна).
5. **Дорога:** упрощённая езда по графу улиц (без открытого мира): сплайн-маршрут, развилки, QTE-события. В UE5 — модульные кварталы на основе реальной планировки улиц (данные OpenStreetMap, лицензия ODbL — требует атрибуции).
6. **Смерть и наследство:** сцена смерти → флешбэк → последняя запись → «Передача смены» → пролог наследника.
7. **Отчёт / метрики / «Летопись».**

## 8.4 LLM: где использовать и где нельзя

**Принцип:** игра полностью проходима **без LLM**. Весь сюжет, все развилки, все 27 концовок написаны людьми. LLM — это слой «живости» поверх авторского контента, а не генератор сюжета.

| Где | Что делает LLM | Режим |
|---|---|---|
| **«Свободный пульт»** (опция) | Игрок говорит или пишет вопрос своими словами. LLM **классифицирует** его в один из авторских вариантов колеса («адрес», «дыхание», «опасность»…) или в «не по делу» | Рантайм, онлайн |
| **Перефраз реплик звонящего** | Варьирует авторскую реплику («Он не дышит!» → «Он… не дышит, кажется…») в рамках смысла и эмоции. Новые факты запрещены | Рантайм, онлайн |
| **Массовые вызовы** (3.4 «12 вызовов», 4.5 «200 вызовов») | Генерирует вариации бытовых звонков-«фоновых» из авторских шаблонов: кто, где, что, эмоция | Офлайн-пайплайн (заранее, на этапе сборки) + ручная вычитка |
| **Инструменты сценаристов** | Проверка консистентности (имена, возраст, флаги между 225 версиями), черновики вариантов, вычитка | Офлайн |

**Модели (Claude API):**
- Основная — `claude-opus-5-5`: офлайн-пайплайны, инструменты сценаристов, проверка консистентности.
- Для рантайма («Свободный пульт», перефраз) старт — тоже `claude-opus-5-5` с `effort: "low"`. Перед релизом замерить задержку и качество на выборке реальных реплик игроков и сравнить с `claude-haiku-4-5`. Целевая задержка классификации — < 700 мс до первого токена. Если `low` effort не укладывается, переходить на более быструю модель на этом маршруте.
- Для классификации — structured outputs (`output_config.format`) с enum из ID авторских вариантов. Модель никогда не возвращает свободный текст в игровую логику.

**Защитные рамки:**
- Системный промпт: роль звонящего, жёсткий список фактов миссии, запрет на новые факты, имена и детали насилия, ограничение длины.
- Тематика игры (18+, насилие, суицид) может вызвать отказ модели (`stop_reason: "refusal"`). Клиент обязан проверять `stop_reason` и при отказе, ошибке сети или таймауте **мгновенно подставлять авторскую реплику**. Для `claude-opus-5-5` включить серверный фолбэк (`fallbacks: "default"` с beta-заголовком `server-side-fallback-2026-07-01`).
- **Сцены, где LLM выключен всегда:** суицидальные переговоры (2.4, 3.4 вызов 7, 4.4, 5.2), сексуальное насилие (любые упоминания), смерть героев, концовки. Там только авторский текст, утверждённый консультантом.
- Кэширование: системный промпт и факты миссии — стабильный префикс с `cache_control`. Переменная часть (реплика игрока) — в конце.
- Приватность: голос и текст игрока не сохраняются на сервере дольше сессии. Опция «Свободный пульт» выключена по умолчанию, при включении показывается согласие.
- Консоли и офлайн: «Свободный пульт» недоступен — используется классическое колесо.

## 8.5 TTS и голос

| Задача | Решение |
|---|---|
| **9 героев и ключевые NPC** | Только живые актёры озвучки (русский), запись в студии + лицевой захват (UE5 Live Link Face) |
| **Плейсхолдеры в прототипе** | Локальный TTS для черновой озвучки всех реплик: Silero TTS (сильный русский), Piper (MIT-код, лицензии голосов проверять по каждой модели). Перед коммерческим использованием проверить лицензии моделей: часть из них некоммерческая |
| **Массовые звонящие** (3.4, 4.5) | Коммерческий TTS с русским языком и лицензией на коммерческое использование в играх, плюс постобработка «телефонная линия» (полоса 300–3400 Гц, шум, компрессия) |
| **Клонирование голоса** | Только с письменного согласия актёра и с оплатой. Голоса реальных людей без согласия не клонируются никогда |
| **STT для «Свободного пульта»** | Whisper / faster-whisper (MIT) локально на PC; на консолях опции нет |

Звук: **FMOD** (бесплатно для инди до порога бюджета) или **Wwise**. Нужны три слоя: «телефонная линия», «рация» (с шумами и обрывами), «Слух» Веры (3D-локализация источников звука).

## 8.6 SDXL и генеративная графика

| Где | Как |
|---|---|
| **Концепт-арт, мудборды** (ночной Воронеж, «Камелия», ЛХК, ЕДДС) | SDXL + ControlNet по фото реальных улиц, снятых командой (свои фото — без чужих прав) |
| **Внутриигровые «фото»** (старые фото в 3.2, фото в «Деле», контактный лист Алины) | SDXL как черновик, финал — дорисовка художником. Ни одного лица реального человека |
| **Текстуры** (обои, плакаты, вывески вымышленных брендов) | SDXL → ручная доработка, тайлинг |
| **Чего не делаем** | Не генерируем реальные логотипы служб, лица реальных людей, реальные вывески бизнеса. Не используем генерацию для финальных персонажей |

Лицензия SDXL (CreativeML Open RAIL++-M) разрешает коммерческое использование с ограничениями по назначению. Её проверяет юрист. В Steam и других магазинах использование генеративного ИИ указывается в форме раскрытия (pre-generated и live-generated content — отдельно, live для LLM-реплик).

## 8.7 Прочее

| Область | Решение |
|---|---|
| Контроль версий | Git + Git LFS (Godot); Perforce или Git LFS (UE5) |
| CI | Сборка + QA-скрипт ветвлений на каждый коммит в `content/` |
| Аналитика (опционально, с согласия) | Какие варианты выбирают в развилках — для «Летописи» (% игроков) |
| Локализация | Русский — основной; английский — второй (строки из Ink через CSV) |
| Доступность | Субтитры с указанием говорящего и звука (важно для «Слуха» и для Кольцова), настраиваемые QTE, режим «без мигания», цветовые схемы для дальтоников (красный / зелёный в START дублируется формой) |
